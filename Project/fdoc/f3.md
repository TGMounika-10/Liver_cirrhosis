# fmod3-manual-entry

**Purpose:** Let the user type lab values directly when OCR fails or only a printed report is available.

## Fields
| Field | Required | Unit | Typical accepted range |
| --- | --- | --- | --- |
| Age | Yes | years | 1 – 120 |
| Gender | Yes | M / F | select |
| Total bilirubin | Yes | mg/dL | 0.1 – 80 |
| Direct bilirubin | Yes | mg/dL | 0.0 – 40 |
| ALP | Yes | IU/L | 10 – 3000 |
| SGPT / ALT | Yes | IU/L | 1 – 5000 |
| SGOT / AST | Yes | IU/L | 1 – 5000 |
| Total protein | Yes | g/dL | 2 – 12 |
| Albumin | Yes | g/dL | 0.5 – 7 |
| A/G ratio | Yes | ratio | 0.1 – 4 |
| Platelet count | Optional | x10³/µL | 5 – 1000 |
| PT / INR / GGT | Optional | s / ratio / IU/L | validated if entered |

Ranges only block *impossible* values; they are not diagnostic cut-offs. The final range list is owned by `bmod3-validation-rules`.

## Behaviour
- Client-side validation on blur and on change; error text appears **beside the field** it belongs to.
- Show the expected unit next to each input and a small "normal range" hint.
- Predict button is disabled until every required field is valid.
- Submits JSON to `POST /api/predict/manual`; server-side errors are mapped back to the matching fields.
- Form data lives in React state only.

## Components
`ManualEntryForm`, `FieldWithHint`, `useLabValidation` (hook)

## Done when
- Entering `albumin = -1` shows an error beside Albumin and keeps Predict disabled.
- Server `422` errors appear on the correct fields.
