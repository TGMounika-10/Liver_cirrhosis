# fmod2-upload-report

**Purpose:** Upload a blood-test report, send it for parsing, and let the user verify the extracted values before any prediction is made.

## Flow
1. User picks or drops a file (PDF, JPG, PNG; DOCX optional).
2. Client checks type and size (default max 10 MB) and shows file name, size, and a preview (image thumbnail or first PDF page).
3. File is sent to `POST /api/report/upload` as `multipart/form-data` with the auth token; a progress bar and status messages are shown ("Uploading", "Reading report", "Extracting values").
4. The backend returns `extracted_values`, `warnings`, and `requires_confirmation: true`.
5. An editable **review table** shows each value with its unit and any warning beside it. The user corrects mistakes and ticks **"I have checked these values."**
6. Only after confirmation is the values JSON sent to `POST /api/predict/manual`, then the user is taken to `/result`.

## Components
`UploadDropzone`, `FilePreview`, `UploadProgress`, `ExtractedValuesTable`, `ConfirmCheckbox`

## Rules
- **Never** call the prediction endpoint before the user confirms.
- Uploaded files are held in component state only; never written to `localStorage`/`sessionStorage`.
- Missing values stay empty and highlighted; they are never filled in silently.
- If parsing fails, show a clear message and a button to switch to Manual Entry (fmod3).
- Predict button stays disabled until all required fields pass validation and the box is ticked.

## Done when
- A wrong OCR value can be edited and the corrected value is what gets predicted.
- Unsupported or oversized files are rejected with a specific message.
