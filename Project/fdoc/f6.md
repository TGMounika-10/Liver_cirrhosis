# fmod6-auth  (NEW)

**Purpose:** Sign-up and login using only **Patient ID** and **password**.

## Screens
### Sign up (`/signup`)
- Patient ID, Password, Confirm password, Show/Hide password toggle.
- Patient ID: 4 – 20 characters, letters, digits, `-` and `_`; unique and not case-sensitive.
- Password: 8 – 64 characters with at least one letter and one number.
- Live checklist under the password field (length, letter, number, match).
- Submit calls `POST /api/auth/signup`; on success the user is logged in and sent to `/upload`.
- `409` (Patient ID taken) shows the error beside the Patient ID field.

### Login (`/login`)
- Patient ID, Password, Show/Hide toggle, "Create an account" link.
- Submit calls `POST /api/auth/login`.
- Failure message is always generic: **"Patient ID or password is incorrect."**
- `429` shows "Too many attempts. Try again in a few minutes."

## State
- `AuthContext` provides `{ patientId, token, login, signup, logout, isAuthenticated }`.
- The token is kept **in memory only** (not `localStorage`); a page refresh requires logging in again. A secure httpOnly cookie is the alternative if persistent sessions are needed.
- Axios interceptor adds `Authorization: Bearer <token>`; a `401` clears the session and redirects to `/login`.

## Components
`LoginForm`, `SignupForm`, `PasswordField`, `PasswordChecklist`, `AuthContext.jsx`, `useAuth.js`

## Rules
- Inputs use `autocomplete="username"` and `current-password` / `new-password` so password managers work.
- Never log or display the password; clear it from state after submit.
- No "forgot password" in v1 (no email or phone is collected). Say this on the signup page: "Keep your password safe; it cannot be recovered."
- Do not put the Patient ID in URLs or analytics events.

## Done when
- Wrong password and unknown Patient ID produce the same message.
- Logged-out users cannot open `/upload`, `/manual`, `/result`.
