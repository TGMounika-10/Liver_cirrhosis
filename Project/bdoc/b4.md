# bmod4-ml-engine

**Purpose:** Load the trained model and generate predictions.

## Responsibilities
- Load `trained_model.pkl`, `scaler.pkl`, feature order, and threshold from `models/` once at startup.
- Apply the **exact** training preprocessing: encode gender (same mapping as training), arrange features in the saved order, then scale.
- Return `probability` (0 to 1) and `risk_category`.
- Use a decision threshold chosen to prioritise **recall** for the high-risk class (stored in `metrics.json`).
- Expose metrics and metadata for `GET /api/model/info`.

## Risk categories (default, adjust after validation)
| Probability | Category |
| --- | --- |
| below 0.35 | Low |
| 0.35 to below saved threshold | Moderate |
| at or above saved threshold | High |

## Training (offline scripts)
`train.py` follows the ML workflow in the spec: clean data, stratified train/validation/test split, fit scaler on training data only, baseline Logistic Regression, then Random Forest and XGBoost, stratified k-fold CV, tune on validation only, evaluate once on the test set, save model, scaler, feature order, threshold, and `metrics.json` (accuracy, precision, recall, F1, ROC-AUC, confusion matrix, subgroup metrics, class balance, dataset size, training date).

## Rules
- Missing optional features are handled the same way as in training (documented imputation), never by guessing.
- Refuse to start if model, scaler, or feature order files are missing or mismatched.
- Do not retrain automatically; retraining needs documented data and metric changes.

## Suggested files
`engine.py`, `preprocess.py`, `thresholds.py`, `train.py`, `evaluate.py`

## Done when
- A known sample returns the same probability as in the training notebook.
- Deployment approval rules in `rules/bias_overfit_underfit_rules.md` are met.
