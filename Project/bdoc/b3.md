# bmod3-validation-rules

**Purpose:** Validate extracted or manually entered values before they reach the model.

## Checks
| Check | Result |
| --- | --- |
| Required field missing (age, gender, total/direct bilirubin, ALP, SGPT, SGOT, total protein, albumin, A/G ratio) | **Error** |
| Wrong type (text instead of number) | **Error** |
| Negative or medically impossible value (outside hard range) | **Error** |
| Very high or low but possible value (outside soft range) | **Warning**: "Please double-check this value" |
| Direct bilirubin greater than total bilirubin | **Error** |
| Albumin greater than total protein | **Error** |
| A/G ratio inconsistent with albumin and total protein | **Warning** |
| Likely unit mismatch (e.g. albumin of 29 instead of 2.9) | **Warning** with suggested unit |

## Behaviour
- Returns `{ valid, errors: {field: msg}, warnings: {field: msg} }`.
- **Never silently changes user data.** Suggested corrections are shown; the user must accept them in the UI.
- Hard and soft ranges live in one config file (`ranges.py`) shared with the frontend documentation.
- Optional fields (platelets, PT, INR, GGT) are validated only when present.

## Suggested files
`validators.py`, `ranges.py`, `unit_checks.py`, `schemas.py`

## Done when
- Unit tests cover each row in the table above.
- Prediction is never called when `errors` is non-empty.
